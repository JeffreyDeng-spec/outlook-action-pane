# Project rules

Start a change with a named mailbox outcome and a synthetic acceptance example. Treat account plus immutable Graph message ID as the work identity. Separate message filing, user actions and completion. Keep the task pane focused on concrete next steps.

Before a pull request, run the offline suite and public-tree check in README.md. For pane changes, exercise the narrow layout, both example accounts, an empty inbox of tasks and a disconnected bridge. Report the interface actually verified. Production sends, account enrollment and deployment require the operator's authorization.

Use generated fixtures under reserved test domains. Never add mailbox exports, credentials, personal identities or real screenshots to Git. Preserve the user's independent categories and existing mailbox state.
